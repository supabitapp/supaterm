# Guest links

Share one thread with someone who needs to follow the work without access to your environment.
Guest links are off by default. Enable **Guest links** in **Settings → Labs** on the host,
then choose **Share with guest** from the thread menu and send the resulting link.
The host must stay reachable through the restricted encrypted guest connection.

A guest can follow messages, reasoning, command output, and shared images. File diffs and
ordinary environment controls are unavailable. Anything printed in a shared conversation may
be visible, so review the thread before sharing it.

Guest messages and attachments wait for your approval. Choose **Send** to submit one using the
thread's current permission mode, or **Dismiss** to discard it. You can do this from web,
desktop, or mobile. The guest cannot answer the agent's approvals for you.

Choose **Stop sharing** to revoke access. Expiry and archiving also end access. Turning off
Guest links pauses existing links; an unexpired, unrevoked link can work again when re-enabled.
Only images authorized by the shared conversation are served; a guest link grants no general
access to host files.
